# ЛР 2. Анализ файлов с событиями

Программа читает CSV или JSONL и считает статистику. Нужен Python 3.11 или новее.
Для самого запуска дополнительные библиотеки не нужны.

## Как запустить

В папке проекта:

```bash
./run.sh analyze examples/events.jsonl --format jsonl
./run.sh analyze examples/events.csv --format csv --output report.json
```

Или без скрипта:

```bash
PYTHONPATH=src python3 -m streamstats analyze examples/events.jsonl --format jsonl
```

Несколько файлов передаются подряд:

```bash
./run.sh analyze first.jsonl second.jsonl --format jsonl --output report.json
```

Файлы в одном запуске должны иметь одинаковый формат. Их события складываются.
Повторы не удаляются. Примеры `events.csv` и `events.jsonl` содержат одинаковые
события; результат для одного из них есть в `examples/expected-report.json`.

## Что лежит в файлах

| Файл | Зачем он нужен |
| --- | --- |
| `models.py` | Проверка полей и даты, класс одного события |
| `errors.py` | Свои классы ошибок |
| `parsers.py` | Чтение CSV и JSONL по одной записи |
| `analysis.py` | Счётчики, фильтры и подготовка статистики |
| `report.py` | Запись статистики в JSON или CSV |
| `__main__.py` | Аргументы командной строки и запуск программы |
| `__init__.py` | Что можно импортировать прямо из `streamstats` |
| `tests/` | Проверки программы |

## Как всё работает

Путь одной записи такой:

```text
файл -> read_json / read_csv -> Event -> filtr -> Stats.add -> write
```

1. `main` получает параметры запуска: имена файлов, формат, куда писать отчёт.
2. `analyze` открывает первый файл и выбирает функцию чтения через `get_read`.
3. `read_json` или `read_csv` берёт одну запись и делает из неё словарь.
4. `Event` проверяет словарь. Если данные неверные, возникает ошибка.
5. `filtr` проверяет ограничения по времени, уровню и источнику, если они заданы.
6. `Stats.add` увеличивает нужные счётчики и обновляет минимальное и максимальное время.
7. Когда файл закончился, `analyze` так же обрабатывает следующий.
8. `write` записывает общий результат. Без `--output` он выводится в терминал.

## models.py подробнее

`LEVELS` — допустимые уровни события. `FIELDS` — обязательные поля.

`vremya(s)` превращает строку вроде `2026-01-02T13:00:00+03:00` в дату и время,
с которыми Python умеет сравнивать другие даты. Всё приводится к UTC:
`13:00+03:00` и `10:00Z` — один момент времени. Если часовой пояс не написан,
считаем, что указан UTC. Одна дата без времени не подходит.

`Event` — обычный класс, в котором лежит одна запись. Вызов `Event(data)`
запускает его `__init__`: он проверяет поля и сохраняет их в объекте.

Например, у объекта `event` можно взять:

```python
event.timestamp
event.level
event.source
event.message
```

`self` внутри класса — тот объект, с которым сейчас работаем.
Например, `self.source = data["source"]` сохраняет имя источника в этом объекте.

Проверки такие:

- `timestamp` должен быть строкой с датой и временем ISO 8601;
- `level` должен быть одним из `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`;
- `source` должен быть строкой, содержащей что-то кроме пробелов;
- `message` должен быть строкой; пустая строка разрешена.

`isinstance(x, str)` проверяет, что значение — строка. Это проверка входных
данных, а не аннотация типа. Аннотаций параметров и возвращаемых значений в коде нет.

## errors.py подробнее

`raise` означает «сообщить об ошибке». `except` — «обработать такую ошибку».

- `StreamStatsError` — общий класс наших ошибок;
- `UnsupportedFormatError` — неизвестный формат;
- `InvalidEventError` — неверная запись;
- `InvalidTimestampError` — неверная дата; это также ошибка записи;
- `CLIConfigurationError` — неправильные параметры запуска.

У ошибки записи сохраняются `filename`, `line`, `reason`: файл, строка и причина.
Поэтому сообщение может выглядеть так:

```text
ERROR: events.jsonl: строка 7: поле timestamp: неверная дата 'bad'
```

`pass` в пустом классе означает, что пока больше ничего добавлять не нужно.
Класс уже наследует поведение своего родителя.

## Почему используется yield

В функциях чтения написано `yield event`. Это отдаёт одно событие и приостанавливает
функцию. Когда цикл попросит следующее событие, функция продолжит работу.
Так весь файл не копится в списке.

Для JSONL запись — одна строка. У CSV внутри кавычек могут быть переносы,
поэтому `csv.reader` сам читает одну целую запись. `reader.line_num` нужен,
чтобы правильно сообщить физический номер строки.

## Как считаются данные

У `Stats` есть:

- `total` — сколько событий подошло;
- `levels` — словарь «уровень -> количество»;
- `sources` — словарь «источник -> количество»;
- `errors` — сколько ERROR/CRITICAL пришло от каждого источника;
- `first`, `last` — самое раннее и самое позднее время;
- `skipped_rows` — сколько неверных записей пропущено.

`Stats.add` обновляет эти поля для одного события. `Stats.merge` складывает
две уже готовые статистики. `Stats.report` собирает словарь для отчёта.

Для top создаются пары `(-count, name)` и сортируются. Минус ставит большие
счётчики первыми. При равных счётчиках сравниваются имена, поэтому порядок
не меняется от запуска к запуску. Затем берём первые `top_n` пар.

Основной проход по N событиям занимает O(N) в среднем. Словари хранят по одному
счётчику на источник, а не сами события. При U источниках и размере наибольшей
записи B дополнительная память — O(U + B). Сортировка источников для отчёта
занимает O(U log U) времени и O(U) памяти. Если все источники разные,
словарей тоже потребуется много.

## Ошибки и отчёт

По умолчанию неверная запись останавливает программу с кодом `2`.
С `--skip-invalid` она пропускается с сообщением `WARNING`:

```bash
./run.sh analyze events.jsonl --format jsonl --skip-invalid
```

`skipped_rows` считает повреждённые записи, включая отфильтрованные по другим
условиям. Одна многострочная CSV-запись считается одним пропуском.
Пустая строка считается ошибочной записью. Полностью пустой файл даёт нулевой отчёт.

Неверный заголовок CSV, ошибка доступа или кодировки останавливают программу
и с `--skip-invalid`. Без заголовка нельзя понять, где какое поле.
Незакрытая кавычка в CSV может объединить остаток файла в одну повреждённую запись.

В JSON есть `total_events`, `by_level`, `by_source`, `top_error_sources`,
`first_timestamp`, `last_timestamp`, `skipped_rows`.
Для пустого результата даты равны `null`. Все пять уровней выводятся, даже
если какой-то встретился ноль раз. Кириллица сохраняется.

Вход открывается только для чтения. `check_out` не разрешает записать отчёт
вместо входного файла, в том числе через ссылки. `save` сначала пишет отчёт
во временный файл, затем заменяет целевой. Если анализ завершится с ошибкой,
старый отчёт останется.

## Дополнительные возможности

Фильтры: начало и конец интервала включаются, `--level` и `--source` можно повторять.
Разные фильтры работают одновременно. Неверные записи проверяются до фильтров.

```bash
./run.sh analyze examples/events.jsonl --format jsonl \
  --since 2026-01-02T10:00:00Z --until 2026-01-02T10:02:00Z \
  --level ERROR --level CRITICAL --source 'база данных' --top 3
```

CSV-отчёт считается из той же статистики:

```bash
./run.sh analyze examples/events.jsonl --format jsonl --report-format csv --output report.csv
```

Его столбцы — `section,key,value`. Секции: `summary`, `by_level`, `by_source`,
`top_error_sources`. Пустая дата даёт пустую ячейку.

`PARSERS` хранит функции чтения по именам. `reg` добавляет новый формат,
`get_read` находит нужную функцию:

```python
from streamstats import analyze
from streamstats.parsers import read_json, reg

reg("custom", read_json)
stats = analyze(["events.custom"], "custom")
print(stats.report())
```

Своя функция чтения принимает `stream`, `filename`, `skip_invalid`, `stats`,
выдаёт объекты `Event` по одному и увеличивает `stats.skipped_rows` для пропусков.
Регистрация работает в текущем процессе. Встроенные имена заменять нельзя.

Из дополнительных заданий сделаны фильтры, registry и CSV-отчёт.
Измерения на 500 МБ, слежения за дописыванием и бинарного формата здесь нет.

## Проверки

Установка для тестов:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m pytest
ruff check .
python -m streamstats --help
```

Если система сообщает, что `venv` не установлен, нужен пакет поддержки
виртуальных окружений для своей версии Python. Быстрый запуск через `run.sh`
виртуального окружения не требует.

Тесты проверяют оба формата, пустые файлы, плохие строки, даты, Unicode,
объединение файлов, top, фильтры и запуск из командной строки.
Есть проверка, что чтение действительно идёт по одной записи и входные файлы
не меняются. Все временные файлы тестов создаются отдельно.
